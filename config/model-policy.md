| 项 | 值 |

## 预设方案

一套预设 = 一个名字 + 一行 `预设默认模型:`。`dsh_setup(preset: "<名字>")` 会把该行的模型写进
上面的 `默认模型:` 行。加预设就在本节里再加一个 `### <名字>` 小节。

### 本项目方案

预设默认模型: deepseek-v4.1-flash

当前项目(RIGOL MRO 等本机工作区)**自己用的规则**:

| 任务类型 | 用哪个模型 | 为什么 |
| --- | --- | --- |
| 默认任务(改代码、跑测试、查文件、批量编辑、脚本) | `deepseek-v4.1-flash` | 快、便宜、够用;绝大多数委派都属于这一类 |
| **文档书写**(PRD / 文档 / 说明 / 报告 / README 这类成文产出) | `gemini-3.7-flash` | 成文产出更吃表达,换它写 |
| **过于复杂**,或**强视觉**(要读截图、图像对齐、离开宿主对话上下文就无法判断) | **不派给 DSH** | 由主模型(调用方自己)亲自完成,别用子代理兜 |

这两个模型都是本机 `$DSH_HOME/settings.yaml` 里**已接入**的模型(provider 都是 `rigol`);
换机器/换实例后要先自己核对一遍,规则见下一节第 1 条。

## 模型选择规则

> 这一节是**给人看的正文**,桥接层不解析它 —— 想改就改,改写成你自己的规则即可。
> 真正会被机器读的只有:第一条 `默认模型:` 行,以及每个 `### 预设` 里的 `预设默认模型:` 行。

**怎么挑:**

1. **先看清有哪些模型,不要凭记忆猜 id。** `dsh_health` 的 `models.providers` 就是**这个 DSH 实例
   已接入的模型清单**(权威来源 `$DSH_HOME/settings.yaml` 的
   `llm-pi-ai.providers.<provider>.models[]` 与 `llm-deepseek.models`,按 provider 分组)。
2. **默认**:省略 `dsh_task` 的 `model` 参数,就走 DSH 自己配置的默认模型(`settings.yaml` 的
   `agent-default-model`)。本文件里的 `默认模型:` 是**调用方该用的规则** —— 也就是首次接入时
   请用户指定的那一个。
3. **文档书写类**:按「本项目方案」换成写文档那个模型。
4. **过于复杂 / 强视觉**:不派给 DSH,主模型自己做。
5. **写错 id 不回退**:传一个本实例没接入的模型 id,DSH 在发请求前就直接失败(`UNKNOWN_MODEL`),
   **不会**静默退回默认模型。所以改规则时先用 `dsh_health` 核对一遍。

**怎么改这份文件:**

- **手改**:直接改那行 `默认模型: <模型 id>`,保存即可(桥接层下次调用就读到新的)。
- **让 agent 改**:`dsh_setup` 会**只改 `默认模型:` 这一行**,其余内容与你的改动一律保留:
  - `dsh_setup(default_model: "<模型 id>")` —— 必须是 `dsh_health.models` 里已接入的模型
    (裸 id 或 `provider/id` 都行);写错会被**拒绝**并列出可用模型清单;
  - `dsh_setup(preset: "本项目方案")` —— 用某个预设的默认模型;
  - `dsh_setup(policy_markdown: "…")` —— **整体替换本文件正文**(谨慎;必须保留一行 `默认模型:`)。
- **加一套预设**:在 `## 预设方案` 下新增 `### <名字>` 小节,并在小节里写一行
  `预设默认模型: <模型 id>`;新小节里的其它文字随便写。
