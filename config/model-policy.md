# 模型策略(桥接层自带的**用户可编辑**文件)

默认模型: deepseek-flash
默认推理强度: max

> 上面两行是**机器可读**的:桥接层每次调用都会重新读它。
> - `默认模型:` 是模型 id;`默认推理强度:` 是该模型在 DSH 里声明过的档位(如 `max` / `high`);
> - 用 `dsh_setup(default_model: "<模型 id>")` 或 `dsh_setup(preset: "本项目方案")` 落盘;
> - 也可以**直接手改这两行**(写裸模型 id,如 `deepseek-v4.1-flash`),保存即生效,不用重启任何东西;
> - 裸模型 id 若在**多条 provider 路由**下都登记过,叶子进程按"哪条路由真的声明了这个推理档位"
>   选路;路由级失败(余额不足 / 凭据缺失 / 档位不支持 / 未知模型)会自动换下一条重试。
>   想钉死某条路由就写 `provider/model`(provider 名见 `dsh_health` 的 `models.providers` 键);
> - 写成 `(未指定)` 时,`dsh_task` / `dsh_health` 的返回值里会带一段「首次接入」引导,
>   请调用方 agent 去**问用户**要一个默认模型(MCP server 自己不跟用户对话)。
> - `默认推理强度:` 只在**用到 `默认模型:` 这一行**时生效(调用方显式指定了别的模型就不掺和);
>   写 `(未指定)` 表示交回 DSH 设置里的档位。

这份文件就是「**选择模型的系统提示词**」:桥接层每次调用都读它,所以任何 harness 拿到的都是当前这份。
本文件**可以随意修改**(改规则、加预设、重写某一节都行)。位置:

| 项 | 值 |
| --- | --- |
| 默认路径 | `<桥接层根>/config/model-policy.md`,即 `~/.dsh/subagent/config/model-policy.md` |
| 链接 | 路径与 `file:///` 链接从 `dsh_health` 的 `modelPolicy.path` / `modelPolicy.fileUrl` 直接取 |
| 环境变量覆写 | `DSH_SUBAGENT_POLICY`(指向别的文件时,以它为准) |
| 机器读哪几行 | 文件里第一条 `默认模型:` 行 + 第一条 `默认推理强度:` 行 + 每个 `### 预设` 小节里的 `预设默认模型:` 行,**其它正文不解析** |

## 预设方案

一套预设 = 一个名字 + 一行 `预设默认模型:`。`dsh_setup(preset: "<名字>")` 会把该行的模型写进
上面的 `默认模型:` 行。加预设就在本节里再加一个 `### <名字>` 小节。

### 本项目方案

预设默认模型: deepseek-flash

当前项目(本机工作区)**自己用的规则**:

| 任务类型 | 用哪个模型 | 为什么 |
| --- | --- | --- |
| 默认任务(改代码、跑测试、查文件、批量编辑、脚本) | `deepseek-flash`(推理强度 `max`) | 快、便宜、够用且能硬扛复杂推理;绝大多数委派都属于这一类 |
| **文档书写**(PRD / 文档 / 说明 / 报告 / README 这类成文产出) | `gemini-3.7-flash` | 成文产出更吃表达,换它写 |
| **过于复杂**,或**强视觉**(要读截图、图像对齐、离开宿主对话上下文就无法判断) | **不派给 DSH** | 由主模型(调用方自己)亲自完成,别用子代理兜 |

这两个模型都是本机 `dsh_health.models` 里**已接入**的模型(provider 名见 `models.providers` 的键);
换机器/换实例后要先自己核对一遍,规则见下一节第 1 条。

## 模型选择规则

> 这一节是**给人看的正文**,桥接层不解析它 —— 想改就改,改写成你自己的规则即可。
> 真正会被机器读的只有:第一条 `默认模型:` 行,以及每个 `### 预设` 里的 `预设默认模型:` 行。

**怎么挑:**

1. **先看清有哪些模型,不要凭记忆猜 id。** `dsh_health` 的 `models.providers` 就是**这个 DSH 实例
   已接入的模型清单**,权威来源是**DSH 自己的登记表**:桥接层让叶子 profile 用
   `--print-model-catalogue` 读 `llm.listProviders()` / `llm.listModels()`(只枚举、不推理),
   结果按 provider 分组返回,`models.source` 会写明是 `native` / `cache`(探针暂时起不来,用上一次的
   结果) 还是 `yaml`(兜底解析配置文件,这时 `modelCatalogueError` 里有探针失败的原因)。
2. **默认**:`dsh_task` 不给 `model` 参数时,**先看你在这份文件里写的 `默认模型:`** —— 它会被当成
   本机默认模型用(能在已接入清单里匹配到才用),同时带上 `默认推理强度:` 那一档;这两行还是
   `(未指定)` 或写了个没接入的 id 时,才交回 DSH 自己配置的默认模型(生效配置里的
   `agent-default-model`;DSH 0.1.7 起该条目是 **per-profile** 的,叶子 profile 那份由安装器从
   本机配置注入)。调用方**自己点了模型**时,策略文件这两行都不参与。
3. **文档书写类**:按「本项目方案」换成写文档那个模型。
4. **过于复杂 / 强视觉**:不派给 DSH,主模型自己做。
5. **写错 id 不回退**:传一个本实例没接入的模型 id,DSH 在发请求前就直接失败(`UNKNOWN_MODEL`),
   **不会**静默退回默认模型。所以改规则时先用 `dsh_health` 核对一遍。

**怎么改这份文件:**

- **手改**:直接改那行 `默认模型: <模型 id>`(要换推理档位就连 `默认推理强度:` 一起改),保存即可(桥接层下次调用就读到新的)。
- **让 agent 改**:`dsh_setup` 会**只改 `默认模型:` 这一行**,其余内容与你的改动一律保留
  (`默认推理强度:` 行原样保留;新模型没有这一档时,用 `dsh_setup(default_model:)` 换完模型后
  记得把它改成 `(未指定)` 或该模型声明过的档位):
  - `dsh_setup(default_model: "<模型 id>")` —— 必须是 `dsh_health.models` 里已接入的模型
    (裸 id 或 `provider/id` 都行);写错会被**拒绝**并列出可用模型清单;
  - `dsh_setup(preset: "本项目方案")` —— 用某个预设的默认模型;
  - `dsh_setup(policy_markdown: "…")` —— **整体替换本文件正文**(谨慎;必须保留一行 `默认模型:`)。
- **加一套预设**:在 `## 预设方案` 下新增 `### <名字>` 小节,并在小节里写一行
  `预设默认模型: <模型 id>`;新小节里的其它文字随便写。
